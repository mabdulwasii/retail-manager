== Overview

This document provides a complete reference of all permissions in the Shop Manager system and their default role assignments.

=== Permission Naming Convention

Permissions follow the pattern: `{RESOURCE}_{ACTION}`

*Examples:*

* `PRODUCT_CREATE` - Create products
* `SALES_READ` - View sales details
* `INVENTORY_UPDATE` - Update inventory

=== Default Role Hierarchy

[cols="1,3"]
|===
|Role |Description

|*SYSTEM_ADMIN*
|Full system access across all tenants

|*OWNER*
|Tenant-wide administrative access

|*MANAGER*
|Shop-level management access

|*EMPLOYEE*
|Operational access for daily tasks

|*INVESTOR*
|Read-only investment analytics access
|===

=== User Listing Endpoints (Added in V25)

The following endpoints provide user listing functionality with optional status filtering:

* `GET /api/users?status={status}` - List all users system-wide (SYSTEM_ADMIN only)
* `GET /api/tenants/{tenantId}/users` - List all users in a tenant (USER_LIST permission)
* `GET /api/shops/{shopId}/users?status={status}` - List all users in a shop (USER_LIST permission)

All endpoints support optional status filtering: `ACTIVE`, `INACTIVE`, `PENDING`.

== Implementation Details

=== Code Reference

All permission constants are defined in:

[source,java]
----
com.princely.shopmanager.shared.constants.PermissionConstants
----

=== Usage Example

[source,java]
----
@PreAuthorize("hasAuthority(T(com.princely.shopmanager.shared.constants.PermissionConstants).PRODUCT_CREATE)")
public ProductResponse createProduct(@RequestBody ProductCreateRequest request) {
    // Implementation
}
----

=== Database Schema

Permissions are stored in the `permissions` table and linked to roles via the `role_permissions` join table.

Default permissions are seeded via Flyway migrations:

* `V12__add_granular_permissions.sql` - Initial permission setup
* `V13__add_missing_permissions_and_fix_role_assignments.sql` - Additional permissions and role updates

=== Multi-Role Support

NOTE: Users can have multiple roles simultaneously. Effective permissions are the union of all assigned roles.

=== Custom Roles

OWNER and SYSTEM_ADMIN can create custom roles with specific permission combinations.

=== System Roles

Default roles (SYSTEM_ADMIN, OWNER, MANAGER, EMPLOYEE, INVESTOR) are marked as `is_system=true` and cannot be deleted.

=== Tenant Isolation

IMPORTANT: All permissions respect tenant boundaries. SYSTEM_ADMIN is the only role with cross-tenant access.
