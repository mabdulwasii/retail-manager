# SSL and DNS Setup for Shop Manager Kubernetes Deployment

## Overview

This guide sets up secure HTTPS access to Shop Manager services using:
- **Ingress Controller**: nginx-ingress for routing
- **cert-manager**: For automatic SSL certificate generation
- **Self-signed certificates**: For local development
- **Local DNS**: Using /etc/hosts for custom domain names

## Prerequisites

- Kubernetes cluster with nginx-ingress controller
- cert-manager installed
- Shop Manager deployed to Kubernetes

## Quick Setup

### 1. Run the DNS Setup Script
```bash
./setup-dns.sh
```

This adds the following entries to your `/etc/hosts`:
```
127.0.0.1 shop-manager.local
127.0.0.1 api.shop-manager.local
127.0.0.1 auth.shop-manager.local
```

### 2. Access Services

**🌐 Frontend (React App)**
- URL: https://shop-manager.local
- Purpose: Main user interface

**🔧 Backend API**
- URL: https://api.shop-manager.local
- Swagger: https://api.shop-manager.local/swagger-ui.html
- Health: https://api.shop-manager.local/actuator/health

**🔐 Keycloak Authentication**
- URL: https://auth.shop-manager.local
- Admin Console: https://auth.shop-manager.local/admin
- Admin Credentials: admin / admin

## Certificate Details

### Self-Signed Certificates
All services use self-signed certificates generated by cert-manager with the `selfsigned-issuer` ClusterIssuer.

**Certificate Secrets:**
- `shop-manager-frontend-tls` - Frontend certificate
- `shop-manager-api-tls` - Backend API certificate
- `shop-manager-keycloak-tls` - Keycloak certificate

### Browser Security Warnings
Since these are self-signed certificates, browsers will show security warnings. You'll need to:

1. Click "Advanced" or "Show Details"
2. Click "Proceed to [site] (unsafe)" or "Accept the Risk"
3. Add permanent exception if prompted

**Chrome**: Click "Advanced" → "Proceed to [site] (unsafe)"
**Firefox**: Click "Advanced" → "Accept the Risk and Continue"
**Safari**: Click "Show Details" → "visit this website"

## Manual DNS Setup

If the script doesn't work, manually add these lines to `/etc/hosts`:

```bash
# Shop Manager Local Development
127.0.0.1 shop-manager.local
127.0.0.1 api.shop-manager.local
127.0.0.1 auth.shop-manager.local
```

### Location of /etc/hosts
- **macOS/Linux**: `/etc/hosts`
- **Windows**: `C:\Windows\System32\drivers\etc\hosts`

## Verification

### Check DNS Resolution
```bash
nslookup shop-manager.local
# Should return: 127.0.0.1

ping -c 1 api.shop-manager.local
# Should ping localhost
```

### Check SSL Certificates
```bash
kubectl get certificates -n shop-manager-secure
# Should show all certificates as READY=True

openssl s_client -connect auth.shop-manager.local:443 -servername auth.shop-manager.local
# Should show certificate details
```

### Check Ingress Status
```bash
kubectl get ingress -n shop-manager-secure
# Should show all ingress with PORTS=80,443
```

## Troubleshooting

### DNS Not Resolving
1. Check `/etc/hosts` entries are correct
2. Clear DNS cache:
   ```bash
   # macOS
   sudo dscacheutil -flushcache

   # Linux
   sudo systemctl flush-dns
   ```

### Certificate Errors
1. Check certificate status:
   ```bash
   kubectl describe certificate -n shop-manager-secure
   ```
2. Delete and recreate certificates:
   ```bash
   kubectl delete certificate --all -n shop-manager-secure
   kubectl delete secret *-tls -n shop-manager-secure
   ```

### Ingress Not Working
1. Check nginx-ingress controller:
   ```bash
   kubectl get pods -n nginx
   ```
2. Check ingress events:
   ```bash
   kubectl describe ingress -n shop-manager-secure
   ```

### Backend/Frontend Connection Issues
1. Check pod logs:
   ```bash
   kubectl logs -n shop-manager-secure deployment/shop-manager
   kubectl logs -n shop-manager-secure deployment/shop-manager-frontend
   ```

## Security Notes

⚠️ **Development Only**: These self-signed certificates are for local development only. For production, use:
- Let's Encrypt certificates
- Commercial CA certificates
- Internal CA certificates

⚠️ **Keycloak Configuration**: Keycloak requires HTTPS for proper OAuth2/OIDC flows. The self-signed certificates ensure this works locally.
