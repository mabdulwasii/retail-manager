# Cloud Sync Setup Guide

## Overview

The **Cloud Sync** feature enables local/embedded installations to backup transaction data to a central cloud installation for analytics, reporting, and business intelligence. This is ideal for:

- **Franchise Operations**: Multiple stores syncing to headquarters
- **Multi-Location Businesses**: Centralized oversight of all locations
- **Remote Monitoring**: Business owners tracking stores remotely
- **Compliance & Audit**: Centralized transaction records
- **Analytics & BI**: Aggregated reporting across locations

---

### Key Features

- ✅ **Offline-First**: Stores operate 100% offline
- ✅ **Automatic Sync**: Scheduled sync (hourly, daily, etc.)
- ✅ **Manual Sync**: On-demand sync via API
- ✅ **Incremental**: Only new transactions synced
- ✅ **Resilient**: Auto-retry with exponential backoff
- ✅ **Secure**: TLS encryption + API key authentication
- ✅ **Privacy**: Optional PII anonymization
- ✅ **Auditable**: Full sync logging

### Cloud Installation

1. **Deployed Cloud Instance** running Shop Manager

4. **Store Registration** in cloud system

### Local Installation

1. **Shop Manager Embedded** version 1.0.0+
2. **Internet Connectivity** (for sync)
3. **Valid Store ID** assigned by cloud admin

## Setup Steps

### Step 1: Cloud Preparation

#### 1.1 Create API Key (Cloud Admin)

```bash
# SSH into cloud server
ssh admin@cloud.shopmanager.com

# Generate API key
curl -X POST http://localhost:8081/api/admin/api-keys \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Store-001-Sync",
    "permissions": ["SYNC_TRANSACTIONS"],
    "expiresAt": "2026-12-31T23:59:59"
  }'

# Response:
# {
#   "apiKey": "sk_live_abc123def456...",
#   "storeId": "STORE-001"
# }
```

#### 1.2 Register Store (Cloud Admin)

```sql
-- Insert store record
INSERT INTO shops (id, name, tenant_id, address, status)
VALUES (
  'STORE-001',
  'Downtown Branch',
  'TENANT-HQ',
  '123 Main St, City',
  'ACTIVE'
);

-- Grant sync permissions
INSERT INTO api_key_permissions (api_key_id, permission)
VALUES ('sk_live_abc123def456...', 'SYNC_TRANSACTIONS');
```

### Step 2: Local Configuration

#### 2.1 Configure Environment Variables

Create or edit `.env` file in local installation directory:

```bash
# Cloud Sync Configuration
CLOUD_SYNC_ENABLED=true
CLOUD_API_URL=https://cloud.shopmanager.com
CLOUD_API_KEY=sk_live_abc123def456...
STORE_ID=STORE-001

# Sync Schedule (cron expression)
SYNC_CRON=0 0 * * * ?  # Every hour at minute 0

# Privacy Settings
ANONYMIZE_PII=false
```

#### 2.2 Advanced Configuration (Optional)

Create `application-custom.yml`:

```yaml
application:
  sync:
    enabled: true
    cloud-endpoint: ${CLOUD_API_URL}
    api-key: ${CLOUD_API_KEY}
    store-id: ${STORE_ID}

    schedule:
      cron: "0 0 * * * ?"  # Hourly
      batch-size: 100
      retry-max-attempts: 3
      retry-backoff-ms: 60000

    privacy:
      anonymize-pii: false
      fields-to-anonymize:
        - customerName
        - customerPhone
        - customerEmail

    resilience:
      circuit-breaker-enabled: true
      failure-threshold: 5
      timeout-seconds: 30
```

#### 2.3 Restart Application

```bash
# Stop application
pkill -f shop-manager-embedded.jar

# Start with new configuration
java -jar shop-manager-embedded.jar
```

### Step 3: Test Connection

#### 3.1 Manual Test

```bash
# Test cloud connectivity
curl -X POST https://cloud.shopmanager.com/api/sync/test \
  -H "X-API-Key: sk_live_abc123def456..." \
  -H "X-Store-Id: STORE-001"

# Expected response:
# {
#   "status": "success",
#   "message": "Connection successful",
#   "storeId": "STORE-001",
#   "cloudVersion": "1.0.0"
# }
```

#### 3.2 Trigger Manual Sync

```bash
# Login to local instance
curl -X POST http://localhost:8081/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin"}'

# Get JWT token from response
JWT_TOKEN="eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."

# Trigger sync
curl -X POST http://localhost:8081/api/sync/trigger \
  -H "Authorization: Bearer $JWT_TOKEN"

# Expected response:
# {
#   "syncBatchId": "uuid-batch-id",
#   "status": "IN_PROGRESS",
#   "recordsToSync": 42
# }
```

#### 3.3 Check Sync Status

curl -X GET "http://localhost:8081/api/sync/logs?limit=10" \

## Sync Schedules

### Common Cron Patterns

| Pattern | Description | Use Case |
|---------|-------------|----------|
| `0 0 * * * ?` | Every hour | Default (balanced) |
| `0 */15 * * * ?` | Every 15 minutes | High-frequency stores |
| `0 0 0 * * ?` | Daily at midnight | Low-frequency stores |
| `0 0 */6 * * ?` | Every 6 hours | Medium-frequency stores |
| `0 0 9 * * MON-FRI` | Weekdays at 9am | Business hours only |

### Dynamic Scheduling

```java
// Programmatically change sync schedule
@Autowired
private CloudSyncConfig config;

public void updateSyncSchedule(String newCron) {
    config.getSchedule().setCron(newCron);
    // Restart scheduler
}
```

## Privacy & Compliance

### PII Anonymization

Enable in configuration:

```yaml
application:
  sync:
    privacy:
      anonymize-pii: true
      fields-to-anonymize:
        - customerName
        - customerPhone
        - customerEmail
```

**Before Anonymization**:
```json
{
  "customerName": "John Doe",
  "customerPhone": "+1234567890",
  "customerEmail": "john@example.com"
}
```

**After Anonymization**:
```json
{
  "customerName": "J**********",
  "customerPhone": "+**********",
  "customerEmail": "j**********"
}
```

### Data Retention

Configure cloud-side retention policies:

```sql
-- Delete synced transactions older than 7 years (compliance)
DELETE FROM synced_transactions
WHERE transaction_date < NOW() - INTERVAL '7 years';
```

## Monitoring & Alerts

### Sync Health Dashboard

```sql
-- Recent sync success rate
SELECT
  store_id,
  COUNT(*) as total_syncs,
  SUM(CASE WHEN status = 'COMPLETED' THEN 1 ELSE 0 END) as successful,
  AVG(records_synced) as avg_records,
  AVG(duration_ms) as avg_duration_ms
FROM cloud_sync_logs
WHERE sync_start_time > NOW() - INTERVAL '7 days'
GROUP BY store_id;
```

### Alert Rules

**Failed Syncs**:
```sql
-- Alert if more than 3 consecutive failures
SELECT store_id, COUNT(*) as failures
FROM cloud_sync_logs
WHERE status = 'FAILED'
  AND sync_start_time > NOW() - INTERVAL '24 hours'
GROUP BY store_id
HAVING COUNT(*) > 3;
```

**Sync Lag**:
```sql
-- Alert if no sync in last 6 hours
SELECT s.id as store_id, s.name
FROM shops s
LEFT JOIN cloud_sync_logs csl ON s.id = csl.store_id
WHERE csl.sync_end_time < NOW() - INTERVAL '6 hours'
   OR csl.sync_end_time IS NULL;
```

## Troubleshooting

### Issue: Sync Failures

**Symptoms**: `status = 'FAILED'` in sync logs

**Diagnosis**:
```bash
# Check error details
SELECT error_message, error_details
FROM cloud_sync_logs
WHERE status = 'FAILED'
ORDER BY sync_start_time DESC LIMIT 1;
```

**Common Causes**:
1. **Network Issues**: Firewall blocking outbound HTTPS
2. **Invalid API Key**: Expired or revoked API key
3. **Cloud Downtime**: Cloud server unavailable
4. **Data Validation**: Transaction data format errors

**Solutions**:
```bash
# 1. Test network connectivity
curl -I https://cloud.shopmanager.com

# 2. Verify API key
curl -H "X-API-Key: YOUR_KEY" \
  https://cloud.shopmanager.com/api/health

# 3. Check cloud status
curl https://status.shopmanager.com/api

# 4. Review transaction data
SELECT * FROM sales_transactions
WHERE id IN (SELECT transaction_id FROM failed_sync_transactions);
```

### Issue: Duplicate Transactions

**Symptoms**: Same transaction synced multiple times

**Diagnosis**:
```sql
-- Find duplicates in cloud
SELECT transaction_number, COUNT(*)
FROM synced_transactions
GROUP BY transaction_number
HAVING COUNT(*) > 1;
```

**Solution**:
```sql
-- Remove duplicates (keep oldest)
DELETE FROM synced_transactions
WHERE id NOT IN (
  SELECT MIN(id)
  FROM synced_transactions
  GROUP BY transaction_number
);
```

### Issue: Slow Sync Performance

**Symptoms**: `duration_ms > 60000` (over 1 minute)

**Optimization**:

1. **Reduce Batch Size**:
   ```yaml
   schedule:
     batch-size: 50  # Reduce from 100
   ```

2. **Increase Timeout**:
   ```yaml
   resilience:
     timeout-seconds: 60  # Increase from 30
   ```

3. **Filter Unnecessary Data**:
   ```java
   // Only sync completed transactions
   transactions.stream()
     .filter(t -> t.getStatus() == TransactionStatus.COMPLETED)
     .collect(Collectors.toList());
   ```

## Security Best Practices

### API Key Management

1. **Rotation**: Rotate API keys every 90 days
   ```bash
   curl -X POST https://cloud.shopmanager.com/api/admin/api-keys/rotate \
     -H "Authorization: Bearer ADMIN_TOKEN" \
     -d '{"apiKeyId":"old-key-id"}'
   ```

2. **Revocation**: Immediately revoke compromised keys
   ```bash
   curl -X DELETE https://cloud.shopmanager.com/api/admin/api-keys/KEY_ID \
     -H "Authorization: Bearer ADMIN_TOKEN"
   ```

3. **Least Privilege**: Grant only necessary permissions
   ```sql
   -- API key should only have SYNC_TRANSACTIONS permission
   SELECT * FROM api_key_permissions
   WHERE api_key_id = 'KEY_ID';
   ```

### Network Security

1. **TLS Only**: Always use HTTPS
   ```yaml
   cloud-endpoint: https://cloud.shopmanager.com  # ✅ Correct
   # cloud-endpoint: http://cloud.shopmanager.com  # ❌ Wrong
   ```

2. **Certificate Validation**: Don't disable SSL verification
   ```java
   // ❌ NEVER do this in production
   // TrustManager[] trustAllCerts = new TrustManager[]{ ... };

   // ✅ Use default certificate validation
   RestTemplate restTemplate = new RestTemplate();
   ```

3. **IP Whitelisting** (Cloud-side):
   ```nginx
   # Allow only known store IPs
   allow 203.0.113.0/24;  # Store network
   deny all;
   ```

## Analytics & Reporting

### Cloud-Side Queries

**Total Sales by Store**:
```sql
SELECT
  s.name as store_name,
  COUNT(st.id) as total_transactions,
  SUM(st.total_amount) as total_sales,
  AVG(st.total_amount) as avg_transaction
FROM synced_transactions st
JOIN shops s ON st.store_id = s.id
WHERE st.transaction_date >= DATE_TRUNC('month', CURRENT_DATE)
GROUP BY s.name
ORDER BY total_sales DESC;
```

**Top Products Across All Stores**:
```sql
SELECT
  product_name,
  SUM(quantity) as total_sold,
  SUM(total_price) as total_revenue
FROM synced_transaction_items
WHERE synced_at >= DATE_TRUNC('month', CURRENT_DATE)
GROUP BY product_name
ORDER BY total_revenue DESC
LIMIT 10;
```

**Store Performance Comparison**:
```sql
SELECT
  s.name,
  COUNT(DISTINCT DATE(st.transaction_date)) as active_days,
  COUNT(st.id) as total_transactions,
  SUM(st.total_amount) as total_sales,
  SUM(st.total_amount) / NULLIF(COUNT(DISTINCT DATE(st.transaction_date)), 0) as avg_daily_sales
FROM shops s
LEFT JOIN synced_transactions st ON s.id = st.store_id
WHERE st.transaction_date >= DATE_TRUNC('month', CURRENT_DATE)
GROUP BY s.name
ORDER BY total_sales DESC;
```
